# 第二页 / 第四页 · 上游启动说明

2026-10-12。这份只讲"跑这两页之前，哪些上游要起着、怎么起、起没起怎么查"。

## 一、现状：为什么老是"服务不成功"

实测和读代码的结论，四条：

1. **日常入口根本不拉上游。** `npm run dev` 走 `scripts/run-project.mjs`（其实是 vinext 起 Next），里面没有任何启动上游的代码；只有 `npm run dev:local` 走 `scripts/start-local.mjs`，那里才会调 `startEmos()`。
2. **三个上游里只有 EMOS 有自动启动。** PA 网关（8790）、Skill Foundry（8765）只有各自的脚本（`services/pa-gateway/run-local.ps1`、`services/skill-foundry` 的 `uv run python -m adapter`），应用这边没有任何地方去拉起它们。
3. **拉起失败看不见原因。** `scripts/emos-process.mjs` 用 `stdio:'ignore'` 起子进程，只在等满 6 秒后抛一句"请检查 Python 版本、端口和数据库权限"，看不到真正的报错。
4. **服务没起时系统静默降级。** 记忆同步会一直停在 `pending`（不报错、也不失败），技能生成的请求会变 `failed`——界面上都看不出来，所以才会出现"功能看着有、实际跑不通"。

## 二、怎么起（一条命令）

新增了启停工具（放在我们自己的目录，没动别人的脚本）：

```bash
cd C:\Users\35057\Desktop\elfred-v28-sync
node tools/page2-checks/upstreams.mjs status          # 看四个上游现在什么状态
node tools/page2-checks/upstreams.mjs start all       # 按依赖顺序起：FreeTodo → EMOS → 网关 → Foundry
node tools/page2-checks/upstreams.mjs stop all        # 停掉（只杀它自己拉起来的进程）
```

也可以单个起：`start emos` / `start gateway` / `start foundry` / `start freetodo`。

日志和 pid 都在 `.elfred-data/upstreams/` 下（`<名字>.log` / `<名字>.pid`），起不来先看那个 log。

## 三、四个上游是什么、端口、依赖

| 上游 | 端口 | 启动方式 | 备注 |
| --- | --- | --- | --- |
| FreeTodo | 8001 | `python -m lifetrace.server`（cwd 指向它的仓库） | Skill Foundry 的上游，不起它 Foundry 起草不了。路径用 `ELFRED_FREETODO_DIR` 指，默认按本机已知位置找 |
| EMOS 记忆中枢 | 8200 | `python -m src.memory_system.api.elfred_bridge`（cwd `services/emos-memory`） | 要 `ELFRED_MEMORY_HUB_TOKEN`（≥32 位）和 `ELFRED_EMOS_DATABASE` |

Jev 是外部服务（TypeSafe），本地起不了，只能配 key；没连上时判定不会落记录。

## 五、10-12 实测记录

**起了三个上游之后的效果**（EMOS 8200、PA 网关 8790、Skill Foundry 8765）：

- `status` 三条都是"通"：EMOS 返回 `契约 elfred-memory-v1`、网关 `/health` 通过、Foundry `/v1/elfred/health` 通过。
- 闭环探测（25 步）从 **21 通** 变成 **22 通**：
  - 记忆同步：`pending` → **`synced`**。
  - PA 网关：命令能登记、网关能应答。
- 仍然断的三条，原因都清楚：
  1. **「用它做一件事」**进不了会话——后端没有 `conversation.ensure_personal`（真缺口，要补代码）。
  2. **技能生成**：Foundry 起来了，但它的上游 **FreeTodo 没起来**（日志：`ModuleNotFoundError: No module named 'loguru'`）。它自己的依赖清单在 `FreeTodo-main/requirements-runtime.txt`（33 项，含 chromadb、sentence-transformers 这些大件），**装完依赖再起 FreeTodo，这条才可能通**。
  3. **Jev 判定**：外部服务，只能配 key。

**为什么 FreeTodo 起不来这件事之前没人发现**：它不在这个仓库里，依赖也没装，而应用侧失败时只留下一句 `failed`，没有指向原因。工具现在会把启动日志的最后几行直接打出来（上面那条 `loguru` 就是这么看到的）。
