# 原稿要求 → 当前实现 → 验证（2026-09-28）

以 `D:\软工任务` 中首页、消息页、私聊、群聊、社区第一性原理设计说明和后续确认台账为产品依据；整编版仅用于定位。后续确认覆盖早期冲突项。本表记录这次修复后的可验证状态，不把外部平台未接入写成完成。

| 原稿要求 | 代码实现 | 验证 |
| --- | --- | --- |
| 初始化对话只在会话内展示，不把内部提示词当普通任务标题 | `onboarding.mjs` 标记后台任务；任务列表和搜索过滤；初始化会话继续读取实际回执 | `at-onboarding.test.mjs`、手机端初始化流程 |
| 真人发起共创时填写目标、已有基础、开放任务、验收、参与、公开范围、审核人与费用；明确无期限；预览后本人发布 | `community.mjs` 的私有草稿、`project.brief.update` 和发布校验；`CommunityComposer`、`ProjectBriefEditor` 提供填写、预览、确认 | `handoffs.test.mjs` 缺项阻断与私有来源隔离；手机端创建→预览→发布 |
| 首个公开任务可直接认领，公开约定变更需成员重新确认 | 首次发布把 Brief 的开放任务创建为真实任务位；一般认领和副本沿同一任务位，更新 Brief 后旧公开约定保持到本人再发布 | `original-requirements.test.mjs` 的任务身份、认领、副本和变更验证 |
| 社区内容只能真人公开；私人资料不自动带入共创帖 | 社区命令拒绝 Agent 发布；公开帖仅复制经确认的 Brief 字段 | `completion.test.mjs`、`handoffs.test.mjs` |
| 项目成员持续共享工作状态；过程稿与正式贡献、公开作品有区分 | 项目副本、任务进度、阶段稿、提交、采纳、发布独立；看板只显示已共享阶段预览 | `project-progress.test.mjs`、`original-requirements.test.mjs` |
| 对阶段版本反馈，变化后下游重验；非成员不得查看 | `project.feedback` 固定阶段版本；旧版本只保留历史，不再可用于执行；成员权限过滤 | `project-progress.test.mjs`；`project-live.test.mjs` 双账号 SSE 与非成员拒读 |
| 临时调度使用发起者额度，生成建议后经本人验收才能共享；不得代成员接受变更 | `project.dispatch` 与 `project.dispatch.publish`；协调说明在成员讨论区可见，任务位变更继续要求成员重新确认 | `original-requirements.test.mjs` 公共预算和共享门控 |
| Agent 朋友圈同事件一个主帖；其他 Agent 按事件动机评论；公共社区只由真人发布 | 私人朋友圈保留事件主帖。初始化或朋友圈筛选中明确开启后，每日最多 3 次、每次最多 1000 本地额度，另一 Agent 基于已验收成果或真实资讯摘要自动评论；结果标待核对并在卡片内显示 | `feed-peer.test.mjs` 验证同事件一帖、真实模型回执、上限与搜索隔离 |
| 本人纠正后形成可检验规则，经过测试、批准、回退才用于未来任务 | 拒绝任务并给具体反馈会自动形成同 Agent 领域候选方法；既有双留出评估、本人发布和回退继续使用 | `runtime.test.mjs` 验证未批准不生效、发布后仅同领域、快照不受回退改写 |
| 断线后恢复协作状态，不把“已同步”等同“已审核” | 项目事件经 SSE 推送，游标续接；客户端刷新受权限过滤的快照，显示同步时间；过程稿必须本人审查才共享 | `project-live.test.mjs`、`media-http.test.mjs`、`events-pagination.test.mjs` |

**边界与剩余验收：** 当前共创采用隔离副本和审核合并；原稿并未要求首版同文件并发编辑。微信、Apple、短信和邮件验证仍缺平台资质、回调域名与发送服务；Jev、EmoS、EvoMap/Tutti 的原生服务也需各自接口与凭据。它们不能用通用模型 Key 冒充。真实目标用户的共创理解测试、真实第三方服务联调和持续使用质量观察仍需在具备条件后验收。
