# 第二、四页合并说明

数据源统一为 V28 登录会话、SQLite 对象和命令服务；不依赖已下线的独立 `elfred-page2-api`。

## 已接通

- 工具、记忆、文档、成果、关系和个人资料读取同一会话。新账号显示空态，切换账号清除上一账号投影。
- 文件、网址、任务创建和 Agent 持久对话沿用现有命令服务。
- 编辑资料逐字段保存；一次操作等待一次 `profile.save` 完成，失败保留编辑内容。空昵称保存为“路人”。
- 头像、封面和等级显示偏好保存并在刷新后恢复。媒体写入不覆盖其他资料字段。
- 第四页动态读社区那份 `post`（真人发的），点赞/收藏是真操作；勋章两边共用服务端算的同一份。
- 设置保留现有权限、数据导出、调用配额与供应商对账。**上游服务状态不摆到界面上**：
  `GET /api/elfred/health/deps` 留在后端，排查时直接打这个接口；设置页不出现 EMOS / Skill Foundry /
  网关 / Jev 这些名字（普通用户看不懂，也处理不了）。
- **能力卡的分与等级**：`core/capability-score.mjs`。只由"完成并验收过的成果"推，使用次数不参与；
  0 项成果不给分；分是置信下界（μ−1.5σ），外部可核对权重 1.0、本人验收 0.8；等级按成果门槛 + 分数下界定档。
- **能力卡的说明书**：`core/skill-markdown.mjs` 把 SKILL.md 拆成"它能替你做 / 步骤 / 输入 / 交付 / 边界"，
  卡面小字取其中一句话；原文按 markdown 渲染在"完整说明"里（以前是压成一行字，看着像乱码）。
- **第一张能力卡怎么来**：`core/card-onboarding.mjs` 的**分支选择树** —— 每页 3 个选项，选完决定下一页；
  路径上的每个选项除了指向某张卡，还带"内容片段"（改交付、改注意、加输入），
  所以**同一张卡走不同路径就是两份不同的 skill**。界面只有"答题 → 确认 → 生成"三层：
  确认页复述这一次的选择 + 它是什么、交付什么（不放「再细一点」「看完整说明书」），
  答题页只有三个选项（不放"自己说一句"的出口；要按自己一句话生成走接口的 `custom_text`）。
- **「用它做一件事」怎么进对话**：说明书不再倒进输入框 —— 它变成对话页输入框**上方**的一张附件卡
  （卡名 + ✕），用户照常写自己的话；发送时把说明书拼在消息正文里，发出去的内容和改动前一致。
  用户一个字都没写时，用附件自带的那句"我想用「…」做一件事，请先帮我明确目标"兜底。
- **能力卡组右上只剩两颗圆钮**：「创建工具」（进工具编辑器）和「查看我的工具」（进我的工具页）。
  原来中间那颗"让 Skill Foundry 生成能力卡"按反馈删掉了；`skill.forge` 命令与投影里的 `forge`
  状态都还在后端，要恢复入口只需把按钮加回来（`tools/page2-checks/live-audit.mjs` 里有反向断言：
  这两颗钮要能进对应页，且"让 Skill Foundry 生成"不该再出现）。
- **理解度**：`core/agent-alignment.mjs` 的 `understandingScore`。由成果（外部核对 1.0 / 本人验收 0.35）、
  遗忘（30 天半衰期）、指正惩罚（每条 8%，最多扣一半）和一次性的问卷加分共同决定；可升可降、没有终点。
- **理解度在界面上只有一个口径**：页头胶囊（能力库 / 记忆库）、理解度弹层里的「当前理解度」、
  第四页名字旁那颗胶囊、设置页那一行，全部从 `data/knowledge-data.ts` 的 `alignmentView()` 读
  （它读的是同一次投影写进 `libraryHeader` 的几个字段）。**空态不改数字**：新用户的起点由
  `understandingScore` 给（没见过你 ≈ 一成），界面不再写"空态就显示 0%"。
  后端还没给真数时 `live=false`，四处一起写「—」，不写 0%（0 的意思是"它确定自己不了解你"，是另一件事）。
- **理解度弹层底部三格**：条数 / 持续更新天数 / 记忆可信度读 `buildMemoryView()`（记忆库那一页同一份）。
  记忆可信度 = 已确认的记忆里档位到"场景已验证 / 跨时间稳定"的占比（`memory-validity.mjs` 维护的字段，
  前端只数一遍）；一条都没确认时是 `null`，界面写「—」。
- **空态的按钮口径**：`?empty=1` 只是手动预览开关，它只影响"画不画空块"，不参与任何数字。
- **五维能力**：题库、计分、起点与估计共用 `core/dimensions.mjs`；作答由 `questionnaire.submit` 落成
  `dimension_baseline`，`GET /api/elfred/page2/questionnaire` 给题面。每维数字来自测试起点 + 每条被本人
  验收的成果自己的表现；没测过、成果又不够 3 条的维不给数字。

## 明确不做的（别再恢复旧路径）

- 「记忆体检 / 归档」「卡片真跑一次」：旧独立后端有过实现，合并进主库后没有对应接口。
  产品口径是"留存但不展示"，所以入口和那两个永远返回"未接通"的空壳函数都删掉了；
  以后要做应当接 EMOS 侧的体检接口，而不是恢复 `/page2/memory/hygiene`。
- 「待确认素材」收件箱：投影里 `pending` 恒为空，等于永不出现的死界面，已删除。
  导进来的东西直接进"文档"，任务验收产物只出现在"成果"里，不再同时在两处出现。

## 文件怎么分层（2026-09-29 重构，改之前先看这里）

| 文件 | 只管什么 | 不许做什么 |
| --- | --- | --- |
| `api/page2-types.ts` | 数据契约（纯类型） | 不写逻辑 |
| `api/page2-projector.ts` | 快照 → 视图的**纯投影** | 不碰 React、不发请求、不存状态 |
| `api/page2-runtime.ts` | 当前快照 / 命令通道 / 订阅者 / `usePage2Live` | 不拼业务参数 |
| `api/page2-api.ts` | 动作层：把界面操作翻译成命令或读取；对外门面 | 不自己算分数（那是 core 的事） |
| `api/page2-store.ts` | 跨页交接条（打开哪张卡 / 带哪张 skill 进对话） | 不存产品状态（分数、等级、裁定都不许放这） |
| `data/pages24-view-data.ts` | 视图数据 + 演示兜底（只读） | **不许**在别处改它的内容 |
| `data/pages24-live.ts` | 真数据"就地替换"（唯一改上面那些常量的地方） | offline 时什么都不做 |
| `data/knowledge-data.ts` | 数据层入口（barrel，页面照旧从这 import） | — |
| `styles/knowledge-library.module.css` | 第二页自己的块：卡片组 / 知识库 / 能力洞察 / 导入 | 只给那三个屏用 |
| `styles/knowledge-sheet.module.css` | 弹层那几件：卡片详情 / 理解度面板 / 勋章 / 阶梯 | 只给那四件用 |
| `styles/knowledge.module.css` | 跨屏共用的（页头 / 资料 / 设置 / 被多组共用的选择器） | 一个类只能有一个家 |

为什么这样分：投影和公式是"页面上每个数字"的唯一来源，抽出来之后能被 Node 直接单测
（`tests/elfred/pages24-projection.test.mjs`、`pages24-scoring.test.mjs`），
不必开浏览器点；口径、地址白名单这类容易改一处忘一处的东西也都收成一份。

样式那份同理：`knowledge.module.css` 原来 1900 行被 11 个组件共用，现在按"谁在用"分成三份。
拆的时候记住三条（都踩过）：
1. **一个类只能有一个家**：`.statRow, .statPlain` 这种跨组选择器，涉及的类一律留在共用文件，
   否则选择器里的哈希对不上、样式静默失效；
2. **`@media` 里也要整棵搬**，只搬顶层块会把媒体查询里的规则落下；
3. **替换引用要带词边界、名字长的先替**（`styles.stat` 会顺手把 `styles.statRow` 改掉）。
改完跑 `css-classes.mjs`：每份文件"定义了没人用 / 用了没定义"都必须是 0。

## 防回归的三道闸

1. `node tests/run-product-tests.mjs`（`npm test`）：产品级断言（空态、降级、串号…）。
2. `npm run test:runtime`：含投影 / 分数 / 理解度 / SKILL.md 解析 / 四个上游的目标级单测。
3. `node tools/page2-checks/live-audit.mjs`（真浏览器）：造账号跑第二/四页，9 项断言 + 截图；
   `node tools/page2-checks/flows-audit.mjs`：六条用户流程（记忆库 / 编辑资料落库 / 上游状态 /
   导入 / 轻量测试→雷达 / 动态点赞）；`node tools/page2-checks/css-classes.mjs`：CSS 类清点；
   `node tools/page2-checks/audit.mjs`：静态审计（命令有没有人接、读了没人写的对象、危险渲染、
   乱码注释、门槛表重复定义、本地存储里存了什么、门面有没有死导出）。
   `node tools/page2-checks/onboarding-audit.mjs`：能力卡初始化的全流程（空态 → 选择树每页 3 个选项 →
   预览复述 + 完整说明书 → 生成 → 卡组与卡详情 → 真的用它跑出一份回执 →
   同一张卡换条路内容不同 / 自己说一句（命中·命不中）/ 再来一张四条边界）。
   三个真机探针共用一个入口函数 `_page.mjs`（等应用起来，必要时跳过首次对齐页）。
