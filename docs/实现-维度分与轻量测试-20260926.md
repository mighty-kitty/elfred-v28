# 实现：用户五维分（人级）+ 新用户「轻量测试」

> 这份文档记两轮：
> **第一轮**把"卡的分（skill 级）"和"人的五维分（人级）"拆开；
> **第二轮**（同日，按用户口径）改成 **测试给起点 · 起点也进综合分 · 题库换 IPIP 混合**。
> 现在这份写的是**当前真实状态**，自测全绿（清单见最后一节）。

## 一、主体拆开：卡的分 ≠ 人的分

### 之前错在哪
`insight.axes_now()` 是"该维度下所有卡的分数按成果数加权平均" —— 直接把 **skill 的分**
当成了 **人的能力**。多建几张卡就涨、随手的小事和难事一个待遇、样本少也不打折、久了也不会退。

### 现在怎么算（`app/services/dimensions.py`）
每维维护一个后验 `(θ, σ)`：**起点 = 那份轻量测试**，**观测 = 每条成果自己的表现分**，
闭式高斯更新：

```
precision = 1/σ0² + Σ w_i/τ²
θ         = (θ0/σ0² + Σ w_i·y_i/τ²) / precision
σ         = sqrt(1/precision)
lower     = θ − 1.5σ        （保守值；与卡的分同一坐标系）
```

| 参数 | 值 | 含义 |
|---|---|---|
| `τ` | 12 | 单条证据的观测噪声。**调小 = 做一件事就跳一大截**（用户明确说过"随手做一件事就 64 分不对"），所以给宽一点 |
| `σ0` | 10（+ 最多 4） | 起点的标准差；作答越不一致（正/反向项打架）给得越宽 |
| 半衰期 | 30 天 | 证据按 `0.5^(龄期/30)` 衰减 → **久了会退** |
| `MIN_EVIDENCE` | 3 | 够 3 条才算"这一维站住了"；**没做过测试**的账号要靠这 3 条才给数字 |
| 权重 `w` | 外部可核对 1.0 / 本人验收 0.35 / 未验收或纯代做 0.2；带指正记录 ×1.2 | 来源越硬，说话越算数 |
| 难度校正 | 小 0.9 / 中 1.0 / 大 1.15 | `y' = 50 + (y−50)/b` |
| `START_BAND` | 22 – 52 | 测试起点映射到的区间，**整体压在卡片基线 60 之下** |

为了让"每条成果自己的表现"有据可依，给 `evidence` 表补了两列（`app/core/migrate.py` 幂等 ALTER）：
`outcome`（这一次的表现分）、`difficulty`（这件事多大）。三条写入路径都落：
手动加成果（`/evidence`）、本地真跑 skill（`ingest`）、桥接他那边验收（`bridge`）。

**顺手修掉的一个真 bug**：`POST /evidence` 原来把**每一条**成果都写成
`weight_label="计为 1 次外部验证"` —— 人的维度分是按这个标签读权重的，等于
"自己点一下"被当成"外部证实"，随手一件事就把分推上去。现在统一成 `权重 {w}`（和 bridge/ingest 一致），
而 `_weight_of()` 读不出数字的旧标签按 **0.8（本人验收）** 兜底，**绝不默认成外部级**。

## 二、口径修正（用户 2026-09-26 定，别再改回去）

1. **新用户不画全 0 的图**：没做过测试就还是空态（只有「开始测试」），不是一张全是 0 / 全是未知的五维图。
2. **测完立刻有一张起始的五维图**（22–52，偏低）**和一个综合分**。
3. **起点计入综合分**：不再有"自评不计入综合分"这套东西 —— 起点是坐标系的低端，不是"不算分"。
4. **雷达只有一种画法**：不另画一条淡色虚线、不把某几维标灰。说明只留一句
   「起点来自那次测试 / X 已经按真实成果动过」，**没有别的角标**（原来右边挂过
   「做完事会变，久了也会回落」，用户说多余，删了）。
5. **它是动态模型**：做出成果往上走，**被指正、判错、长期不用会回落**（和理解度同一种性质）。

## 三、题库（IPIP 混合方案，22 题）

| 维度 | 题目来源 | 题数 |
|---|---|---|
| 洞察 | IPIP **开放性**（`o1–o4`） | 4 |
| 交付 | IPIP **尽责性**（`c1–c4`） | 4 |
| 表达 | IPIP **外向性**（`e1–e4`） | 4 |
| 链接 | IPIP **宜人性**（`a1–a4`） | 4 |
| 判断 | **自研情景题**（`j1–j6`，3 档选项） | 6 |

- **许可**：IPIP（International Personality Item Pool）是**公有领域**，可自由翻译、改写、商用；
  我们照它的**原题方向键**走（每题 `key: 1 / -1`，正反向各半：13 正 / 9 反）。
- **为什么不要 IPIP 的情绪稳定性那 4 题**：我们量的是"做事的能力"，不是人格诊断；
  拿"我常有情绪波动"去定「判断」这一维，用户看不懂分数是怎么来的。
- **计分**：选项顺序 = 分值顺序（低 → 高）；反向题翻过来；**每题先归一到 0..1**
  再按维度取平均，最后映射到 `START_BAND`（5 档量表题和 3 档情景题不会因为档数不同被拉高/压低）。
- **作答一致性（guard）**：正/反向项的均值差 —— 一路点"同意"的人在两侧会自相矛盾，
  guard 接近 1 → 起点更不确定（σ 更宽）。**不额外占题位、也不单独算分**（上一版的"校准题"删了：
  用户明确问过"自评不进入综合分这种东西存在的意义是什么"）。
- 题目顺序交错排（同一维的题不挨着），避免答题人被上一题带着走。

## 五、接口口径

- `GET /page2/questionnaire`：题目 + 选项（**不含任何内部字段**：没有 `key`、没有 `guard`）。
- `POST /page2/questionnaire`：存一份 `dimension_baselines`（原样保存作答，可回溯重算；
  `active` 保证一人一份有效起点，重测覆盖并留历史）→ 返回起点值 + `guard` + 最新估计。
- `GET /insight/abilities`：每维 `value / lower / source / samples / missing / uncertainty`，另加
  `baseline / started / verifiedDimensions / minEvidence`。
  `source` 四档：`baseline`（只有起点）· `growing`（起点 + 1~2 条成果）· `evidence`（够 3 条）·
  `insufficient`（没测试也没攒够 → **不给数字**）。
  **`composite` = 有值的维的平均（起点也算）**，仍要求 ≥3 维有值。
- `GET /dimensions/{name}`：`score` 是**这个人**在这一维的估计（不再是一张卡的分）。
- 理解度：做过测试给一点分（一次，重测不累加）—— 它确实更了解你了（实测新用户 10% → 15%）。

## 九、理解度与能力分（2026-09-29 补齐口径）

合并进主库之后，这两套算法曾经**没有跟着搬过来**：页头理解度长期显示 0%，卡片停在"待验证 / Lv.1"。
现在两套都搬进共用 core，前后端同一份，并且有单测钉住旧后端实测过的值。

### 理解度（信任那条线）

`app/v28/core/agent-alignment.mjs` → `understandingScore`。口径与旧后端 `insight.read_alignment` 一致：

```
起点 10%（没见过你 ≈ 一成，不能给 0：0 应该是"它很确定自己不了解你"）
confidence = 起点 + (1 − 起点) × 证据增益 × 遗忘衰减 × 推翻惩罚
  证据增益 = 1 − e^(−(1.0×外部可核对 + 0.35×本人验收) / 6)   ← 渐近，没有"100% 到头"这回事
  遗忘衰减 = 0.5 ^ (闲置天数 / 30)                          ← 30 天没有新证据减半，**它会掉**
  推翻惩罚 = 1 − min(0.5, 指正条数 × 0.08)                   ← 被指正/被顶掉的旧理解真的扣分
做过轻量测试：再 +6 × (1 − 当前/100)，只算一次（表里只有一份有效起点）
档位：理解度 ≥ [0,40,55,70,90,96] 的第几档就是 Lv.几（"初见→可托付"六档）
```

被否定的成果（本人说"这条不对"）**不进证据**，只进指正——旧后端就是这么算的。
界面上"再涨 X 个点（约 N 件成果）"里的 N 由同一个公式试算（`nextEvidence`），不是按平均值估的。

实测对照（单测钉住）：新用户 10% / Lv.1；做过问卷 15%；三件外部可核对的结果 45% / Lv.2。

### 能力分与能力卡等级

`app/v28/core/capability-score.mjs`。口径与旧后端 `scoring.py` 一致：

```
能力分 = 置信下界 L = μ − 1.5σ          0 项成果不给分（给 60 分的"及格分"等于白送）
σ = 8 / √(1 + 成果数)                   证据少 → σ 大 → 一次好运升不了级
一条成果进来：k = 1/(1+权重)，μ += k×(表现−μ)，σ = max(2, σ√(1−0.6k))
  权重：外部可核对 1.0 / 本人验收 0.8 / 未核验 0.3
  表现：本人验收满意 92 / 验收了没给满意度 88 / 本人说这条不对 30
等级：成果数 ≥ [0,3,6,10,15] 且 分数 ≥ 55+(档位−2)×8 的最高档（发现→稳定交付五档）
```

分数**可以落**（被否定的成果会把分拉下来），等级门槛是成果数，所以也不会因为一次低分就掉档。
卡片的"输入 / 步骤 / 交付"不是这套算法的产物，来自 `core/skill-markdown.mjs` 对 SKILL.md 的解析。
