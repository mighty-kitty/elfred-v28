# 第二页 / 第四页 · 上游启动说明

2026-10-12。这份只讲"跑这两页之前，哪些上游要起着、怎么起、起没起怎么查"。

## 一、现状：为什么老是"服务不成功"

实测和读代码的结论，四条：

1. **日常入口根本不拉上游。** `npm run dev` 走 `scripts/run-project.mjs`（其实是 vinext 起 Next），里面没有任何启动上游的代码；只有 `npm run dev:local` 走 `scripts/start-local.mjs`，那里才会调 `startEmos()`。
2. **三个上游里只有 EMOS 有自动启动。** PA 网关（8790）、Skill Foundry（8765）只有各自的脚本（`services/pa-gateway/run-local.ps1`、`services/skill-foundry` 的 `uv run python -m adapter`），应用这边没有任何地方去拉起它们。
3. **拉起失败看不见原因。** `scripts/emos-process.mjs` 用 `stdio:'ignore'` 起子进程，只在等满 6 秒后抛一句"请检查 Python 版本、端口和数据库权限"，看不到真正的报错。
4. **服务没起时系统静默降级。** 记忆同步会一直停在 `pending`（不报错、也不失败），技能生成的请求会变 `failed`——界面上都看不出来，所以才会出现"功能看着有、实际跑不通"。

## 二、怎么起（一条命令）

新增了启停工具（放在我们自己的目录，没动别人的脚本）：

**为什么要有 `dev` 这一条**：`npm run dev` 走 `scripts/run-project.mjs`（vinext 起 Next），实测它**只起界面，不挂 Elfred 的接口**——`/api/elfred/health/deps` 直接 404，页面只能退回演示数据。能同时提供界面和接口的是 `npm run dev:local`（`scripts/start-local.mjs`）。我们的 `dev` 子命令就是"先起上游，再用 dev:local 那个入口起应用"，不修改任何仓库脚本，只是去调它们。

也可以单个起：`start emos` / `start gateway` / `start foundry` / `start freetodo`。

日志和 pid 都在 `.elfred-data/upstreams/` 下（`<名字>.log` / `<名字>.pid`），起不来先看那个 log。

**起了三个上游之后的效果**（EMOS 8200、PA 网关 8790、Skill Foundry 8765）：

- `status` 三条都是"通"：EMOS 返回 `契约 elfred-memory-v1`、网关 `/health` 通过、Foundry `/v1/elfred/health` 通过。

  - PA 网关：命令能登记、网关能应答。
- 仍然断的三条，原因都清楚：
  1. **「用它做一件事」**进不了会话——后端没有 `conversation.ensure_personal`（真缺口，要补代码）。
  2. **技能生成**：Foundry 起来了，但它的上游 **FreeTodo 没起来**（日志：`ModuleNotFoundError: No module named 'loguru'`）。它自己的依赖清单在 `FreeTodo-main/requirements-runtime.txt`（33 项，含 chromadb、sentence-transformers 这些大件），**装完依赖再起 FreeTodo，这条才可能通**。

**为什么 FreeTodo 起不来这件事之前没人发现**：它不在这个仓库里，依赖也没装，而应用侧失败时只留下一句 `failed`，没有指向原因。工具现在会把启动日志的最后几行直接打出来（上面那条 `loguru` 就是这么看到的）。

## 六、技能生成那条链要 FreeTodo 起得来（10-12 追加结论）

一开始想用 `ELFRED_CONTEXT_BACKEND=legacy`（Foundry 自带的回落开关）绕开 FreeTodo，**实测绕不过去**：

- 表现：喂事件成功（`喂了 1 条事件`），但分组起草那步 `POST /v1/elfred/skills/passive/scan` 返回 **HTTP 500**。
- 原因（Foundry 日志堆栈）：`adapter/skill_foundry/passive.py:86` 无条件调 `self.client.list_todos()` → `adapter/freetodo_client.py:48` 抛 `FreeTodoError: FreeTodo unavailable ... 目标计算机积极拒绝`。
- 也就是说这条依赖写死在扫描里，跟 `ELFRED_CONTEXT_BACKEND` 无关。

要让它通，只有两条路：

1. **给 FreeTodo 装依赖再起**（它的仓库 `FreeTodo-main/requirements-runtime.txt`，33 项，含 torch / chromadb / sentence-transformers，本机这三样都没装，预计下载 1 GB 以上）。
2. **让同事在 adapter 里加"没有 FreeTodo 时的降级"**（跳过 todo 扫描、只按已喂事件起草）——这属于 Foundry 的代码，不在我们两页范围。

在那之前，技能生成这条链就是"命令能登记、运行时执行失败"，界面上只会显示没导入新卡。

### 10-12 晚：这条已经解决了，根因不是依赖清单本身

按上面第 1 条装了 FreeTodo 的依赖（装进独立环境 `.elfred-data/freetodo-venv`，用 `requirements-runtime.txt`，约 1.2 GB），起服务后 `/api/todos` **还是 404**。继续查才发现真根因：

- FreeTodo 启动日志里有一行 `Failed to register module ...`（loguru 把占位符吞了，看不到详情）；
- 直接复现它的导入：`lifetrace/routers/todo.py:23` → `from lifetrace.services.icalendar_service import ICalendarService` → **`ModuleNotFoundError: No module named 'icalendar'`**；
- 那份 `requirements-runtime.txt` 里没有 `icalendar`，所以 todo 路由一直注册不上，`/api/todos` 就是 404，Foundry 扫描自然 500。

补装 `icalendar` 后：

- `/api/todos` → **200**（本机 200 条待办）；
- Skill Foundry 的扫描不再 500；
- 闭环探测里"技能生成"这条从断变通：**导入 3 张能力卡（source=foundry）**。

所以启动说明里那句"装完依赖再起 FreeTodo"要补一条：**`requirements-runtime.txt` 不全，至少还要补 `icalendar`**（工具已经会用 `.elfred-data/freetodo-venv` 里的解释器起 FreeTodo）。

## 八、10-12 补：整套启动能跑通，以及踩到的两个环境坑

一条命令跑通：`node tools/page2-checks/upstreams.mjs dev`

- 上游四个端口（8001 / 8200 / 8765 / 8790）+ 应用 3000 全部起来；
- `http://127.0.0.1:3000/v28` → **200**（页面正常渲染）；
- `http://127.0.0.1:3000/api/elfred/health/deps` → **401 `请先登录`**（说明接口真的挂上去了，只是没登录；换成 `npm run dev` 时这里会是 404）。

**坑一：`node_modules` 不能跨目录做 junction。** 为了省空间，一开始把它链接到别的副本，结果 Turbopack 直接报
`Symlink [project]/node_modules is invalid, it points out of the filesystem root`，应用起不来。改成在仓库里 `npm ci` 装一份真的才行。

**坑二：C 盘 0 GB 可用。** 装依赖时报 `ENOSPC`；实测剩余空间 0.00 GB。清掉 `AppData\Local\Temp`（3 GB）和 npm 缓存后剩 3.94 GB，才装得下 node_modules（约 0.7 GB）。这类"服务老是起不来 / 网络时好时坏"的怪现象，空间不够也会表现成那样。桌面上 `纪念-Elfred历史版本` 占 **22.45 GB**（一堆历史副本），要长期缓解得靠清理它。

## 九、工具加了两条（10-12）

- `node tools/page2-checks/upstreams.mjs preflight` —— 开工前体检：C 盘剩余空间（低于 5 GB 会提醒）、`node_modules` 是不是符号链接（Turbopack 会拒）、五个端口占用情况、FreeTodo 解释器和 uv 在不在。今天踩的三个坑都在这张表上。
