# 调研：冷启动引导与渐进式卡片（Hyperknow × LobeHub）

日期：2026-09-29。起因：9-27 会议纪要里对我们"第一张能力卡怎么生成"的口径变了——
从"跟 Elfred 对话里长出来"改成「**固定选框初始化 + 渐进式卡片引导**」，并要求参考两个产品。
这份文档只做两件事：把这两个产品的真实做法讲清，以及把它翻译成我们第二页能落地的形态。
**不含任何代码改动**，是给人看的调研记录。

## 0. 先对齐两个名字

会议纪要写的是「Hypernote、Lobihub」，按会里给的域名，实际是：

| 纪要里的写法 | 实际产品 | 地址 |
| --- | --- | --- |
| Hypernote | **Hyperknow** | agent.hyperknow.io（App）／hyperknow.io（官网） |
| Lobihub | **LobeHub**（开源项目 lobehub/lobe-chat） | app.lobehub.com |

顺带一提：LobeHub 是开源的，所以它的引导可以**读代码**考证，不是靠猜；Hyperknow 的引导在登录之后，
只能从官网和它演示里的首屏推断——这一点下面会标出来。

## 1. LobeHub：它的冷启动是怎么搭的

### 1.1 流程

```
Telemetry（可跳过） → ResponseLanguage → FullName → Interests（选框） → ProSettings → AgentPicker（卡片挑选） → 完成
```

每一步都是"一句话标题 + 一组可点的东西"，可以回退，可以跳过（Telemetry 和最后的 AgentPicker 都留了跳过入口），
每一步都有埋点（step 名 / 序号 / 所属流程），加载时是骨架屏而不是空白。

### 1.2 四条关键机制

**① 选框不是问卷，是"筛选器"。**
`Interests` 一步给 17 个预定义领域（business、coding、design、education、finance-legal、health、hobbies、
hr、investing、marketing、operations、parenting、personal、product、sales、writing），每个带图标、**可多选**，
并留一个"其它 → 自己写一句"。选完立刻映射成"市场分类"，**下一步的卡片按这些分类优先排序、并可按分类筛选**。
选框的意义不在于收集信息，而在于决定"接下来给你看什么"。

**② 渐进式 = 一次一句话 + 一层卡片。**
标题用一个统一组件：产品头像 + **打字机逐字浮现**的一句话（同一句话会给多个候选文案，按语言挑一条）。
它不铺长文案，不一次给全量选项，一次只推进一步。

**③ 卡片本身就是选项。**
卡片结构很简单：方形头像 + 标题 + 一句描述；选中时右侧出现对勾；整张卡可点、可键盘操作（`role=button` + `aria-pressed`）。
上方有分类 tab（全部 / 各分类），下方是卡片网格。

**④ 选完立刻"装上就能用"，后端同时产出两样东西。**
选中 → 把这些 agent 装进账号 → 结束引导 → 跳到目标页；与此同时后端并行跑两条流程：
一条把答案整理成**用户画像**，一条据此**推荐第一个任务**。也就是说：引导结束的那一刻，用户手里
不只是"设置好了"，而是"能用 + 有事可做"。

## 2. Hyperknow：它的形态

定位是学习陪伴：把任意学习目标变成一对一课程（讲义、速查表、测验、练习、互动视频），
卖点是"学你的课程、文件、目标、学习风格"。

它官网演示里给出的登录后首屏是：一句 **Ready to learn something new?** + 一个极简输入框，
输入框里预填了示例（"Look into my Canvas, and generate a set of quizzes and flashcards from the lecture slides"），
下面只有附件和 Tools。

它的冷启动更像"**给目标 + 给材料 → 生成课程**"，不是选选项。
**能直接借的是那条例示式引导**：用一段示例告诉用户"该怎么提要求"，这跟 LobeHub 的
"其它 / 自定义输入"是同一个作用——给不知道怎么开口的人一条台阶。

> 说明：Hyperknow 的选框式引导我**没有看到**（在注册之后），上面的结论只基于官网与现代演示首屏，不做过度推断。

## 3. 可以借到我们产品上的机制

| 它怎么做 | 我们对应做什么 |
| --- | --- |
| 选框 → 分类 → 决定下一步给哪些卡、什么顺序 | 第一组选框按我们的**五个系统**（探索/参谋/创作/连接/执行）分类，选中的直接决定生成哪张能力卡 |
| 一次一句话 + 一层卡片，可回退可跳过 | 每一步只解决一个问题；给"其它"出口；允许跳过（跳过就用默认） |
| 卡片 = 头像 + 标题 + 一句描述 + 选中标记 | 与我们现在的能力卡同构，不用另造一套视觉 |
| 选完立刻装进账号，且后端同时产出"画像 + 第一个任务" | 生成完 = **一张可用能力卡 + 一条任务草稿**，卡片旁直接给「用它做一件事」 |
| 用示例提示教用户怎么表达（Hyperknow） | 选框旁边给"例如：帮我把每周的会议记录整理成待办"这类示例 |
| 每步埋点、进度可见 | 初始化的每一步也记一笔（我们已有 trace/usage 的记账习惯），失败能定位 |

## 4. 落到第二页的具体形态（草案）

新用户进第二页，能力卡组是空态 → 走三步初始化（不是问卷、不测性格）：

| 步 | 屏幕上是什麼 | 作用 |
| --- | --- | --- |
| 1 | 一句话："你想让 Elfred 先帮你做哪件事？" + 8~12 张卡（按五个系统各 2~3 个）**可多选** + "其它：一句话描述" | 决定第 3 步生成哪张能力卡（借 LobeHub 的"选框当筛选器"） |
| 2 | 一句话："这件事你要它怎么做？" + 固定选项：先给结论／先给过程 · 简短／详细 · 是否引用来源 · 是否要独立复核 | 这些正好写进我们已有的**能力卡说明书**和**记忆偏好**，不新增概念 |
| 3 | 确认页："我们将给你第一张能力卡：**X**（能做到…）"，一句"以后按你验收过的结果慢慢变" | 落成一张 `skill`（Lv.1 发现、0 成果）+ 一条任务草稿，旁边给「用它做一件事」 |

三条与会议口径对齐的地方：① 主入口不再是"跟 Elfred 说一句话"（纪要里明确要摒弃纯文本对话引导）；
② 第 2 步**不做性格测试**（纪要里说那类问卷暂时搁置、等 AB 测试）；③ 结束即有卡可用，不是只给一张卡。

## 5. 需要拍板的三件事

1. **第一步的选项表**：按五个系统各出 2~3 个候选（我可以先起草），还是你们已有一版？
2. **卡片内容怎么来**：按选项拼模板（快、确定、不花钱）／过一次模型把选项翻成说明书（复用现有 SKILL.md 解析）／
   直接让 Skill Foundry 起草。
3. **旧出口怎么处理**：现有的「去和 Elfred 说」是彻底去掉，还是降级成次级入口。
