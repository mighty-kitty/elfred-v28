# 设计：第一张能力卡的初始化流程（v1）

日期：2026-09-29。目标：把"新用户的第一张能力卡怎么来"从**纯文本对话引导**换成
「固定选框初始化 + 渐进式卡片引导」（9-27 会议口径），并且结束那一刻卡就能用。
这份是设计稿，不是实现；实现前需要拍板的点列在第 7 节。

## 1. 设计依据

三条来自调研（详见《调研-冷启动与渐进式卡片引导.md》）：

1. **选框不是问卷，是筛选器**——选项决定"下一步给你看什么"，而不是收集资料（LobeHub 的兴趣领域 → 分类 → 卡片排序）。
2. **一次一层**——每屏一句话 + 一层可点卡片，可回退、可跳过、有"其它"出口。
3. **结束即可用**——选完立刻产出可用的东西（LobeHub 把 agent 直接装进账号，并同时推荐第一个任务）。

三条来自 Elfred 自己的约束：

4. **卡片的分与等级只能由"验收过的成果"推**：初始化只给起点（Lv.1 发现、0 成果、不给分），
   不然又是"随便做一件事就有分"的老问题。
5. **说明书必须是 SKILL.md 那种分节写法**（`## 什么时候用 / ## 怎么做 / ## 交付什么 / ## 注意`），
   这样卡片详情里的"它能替你做 / 步骤 / 交付"能直接渲染出来，不用为初始化再写一套适配。
6. **不测性格**：会议里"能力洞察用问卷"的方案暂时搁置，所以初始化只问"做事方式偏好"，
   不问"你是什么样的人"；偏好进记忆与任务约束，进五维的不进这里。

## 2. 流程总览

```
入口（能力卡组空态 / 首页"创建工具"）
  └─ 第 1 屏「你想让它先替你做什么？」  一次一件事，卡片多选（≤3）
       └─ 第 2 屏「这件事你要它怎么做？」  四组固定偏好，单选，有默认值
            └─ 第 3 屏「即将生成」        预览 N 张卡 →「生成」
                 └─ 生成结果              N 张可用能力卡 + N 条任务草稿 + 一句"之后怎么长"
```

任何一屏都能「跳过」（跳过＝用默认卡），任何一屏都能「返回」。

## 3. 第 1 屏：你想让它先替你做什么？

一句话标题（逐字浮现）+ 卡片网格，按**五个系统**分组（和我们已有的系统口径一致），
每张卡 = 图标 + 标题 + 一句"它能替你做"。**单选，一次只做一张**
（2026-09-29 定：第一次进来只要一张能用的卡，一次给三张会变成一堆没成果的空卡）。

选项表（草案，五系统 × 3）：

| 系统 | 选项（卡片标题） | 生成的能力卡 |
| --- | --- | --- |
| 探索 · 洞察 | 查资料并核实来源 | 资料检索与核验 |
| | 盯住一个主题的变化 | 主题跟踪与变化提醒 |
| | 把一堆资料整理成要点 | 资料整理与要点提炼 |
| 参谋 · 判断 | 比较几个方案给建议 | 方案对比与取舍建议 |
| | 拆解一个问题找原因 | 问题拆解与归因 |
| | 检查一个方案的风险 | 风险审查与应对 |
| 创作 · 表达 | 写一份文档／文稿 | 文稿撰写 |
| | 改一段文字（语气／结构） | 文字修改与润色 |
| | 出一张图的制作说明 | 视觉制作说明 |
| 连接 · 链接 | 准备一段沟通话术 | 沟通准备与话术 |
| | 整理群聊里的行动项 | 协作信息整理 |
| | 找合适的候选人／资源 | 候选匹配与核对 |
| 执行 · 交付 | 把目标拆成可执行步骤 | 目标拆解与步骤 |
| | 安排一次日程／排期 | 排期与依赖安排 |
| | 核对交付物是否达标 | 交付核对与缺口 |

两个出口：

- **其它：一句话描述**——不知道自己属于哪类的，写一句（如"帮我把每周的会议记录整理成待办"），
  只生成 1 张卡，标题取这句话的前 20 字。
- **我不知道选什么**——不硬逼用户选：给一个默认组合（探索「查资料并核实来源」+ 执行「把目标拆成可执行步骤」），
  并说明"先给两张最通用的，之后随时能改"。

## 4. 第 2 屏：这件事你要它怎么做？

四组固定选项，**单选**、都给默认值，所以"不看也能过"：

| 问 | 选项 | 默认 |
| --- | --- | --- |
| 先给什么 | 结论先行 ／ 过程先行 | 结论先行 |
| 篇幅 | 简短 ／ 详细 | 简短 |
| 来源 | 必须引用来源 ／ 可以不引 | 必须引用 |
| 复核 | 要独立复核 ／ 按任务自动判断 | 按任务自动判断 |

这四个答案有三个去处，全部是现有机制，不新增概念：

- 写进卡片的说明书「注意」小节；
- 写进以后每条任务的 `constraints`（这份卡的规矩）；
- 作为**记忆**留下来（归属本人、低风险自动学），这也是新用户让"理解度"从 10% 往上走的第一批真实信号。

## 5. 第 3 屏与生成

**预览屏**：并排列出即将生成的 N 张卡（标题 · 归属系统 · "它能替你做"一句 · 交付什么），
下面一行固定说明：

> 生成后它们的等级是 **Lv.1 发现、0 项成果**；分数和等级只由你**验收过**的结果往上走。

按钮：「生成这 N 张」+「改一下」（回第 1 屏）。

**生成时后端做四件事**（都用现有命令，不加新接口）：

1. 每张卡 `tool.save` + `tool.activate` 落成 `skill`（`kind=Skill`、`system` 按选项、
   `source=onboarding` 以便以后区分"初始化卡 / Foundry 起草 / 手建"）。
2. 每张卡配**一条任务草稿**（`task.create`，compose 模式，目标＝卡标题＋用户那句话，
   验收标准＝卡片的"交付什么"）——草稿不自动跑，维持我们"确认后才运行"的原则；
   卡片详情里本来就有「用它做一件事」，点它直接跑。
3. 记一笔初始化记录（选项、生成了哪几张、耗时），供以后 AB 与推荐用。
4. 卡片进入能力卡组：Lv.1 发现、0 成果、无分数（沿用已定口径）。

**卡片说明书模板**（生成的就是这个形状，不带任何分数承诺）：

```
## 什么时候用
<用户选的那句话／自定义原文>

## 怎么做
1. <该选项对应的固定第一步>
2. <固定第二步>
3. <固定第三步，含"结论先行／简短／引用来源"这些偏好>

## 交付什么
<该选项对应的交付物>

## 注意
<把第 2 屏四组偏好翻译成约束；没有授权资料时保持未知，不编事实>
```

### 5.1 说明书从哪来（三条路，推荐 B）

先说清一件事：**落成一张 `skill` 不需要模型**——`tool.save` 只是写一条对象
（title / instructions / kind / system，另外还支持 parameters 与 workflow），`tool.activate` 点亮它；
模型只影响"instructions 这段文字怎么写"。所以"不接模型"不等于"生成不了 skill"。

| 方案 | 说明书从哪来 | 成本 | 质量与风险 |
| --- | --- | --- | --- |
| **A 纯模板** | 选项 + 偏好填空到固定骨架 | 0 | 稳、可审；但参数味重，"其它"自由文本拼出来很空 |
| **B 模板 + 其它走模型（推荐）** | 15 张预置卡用模板；只有"其它"那句自由文本过一次模型，翻成同格式说明书 | 每次初始化最多 1 次调用，而且只在用"其它"时 | 预置卡准、自由输入也不至于空；需校验与降级 |
| **C 全走模型** | 每个选项都让模型写 | 3 次调用、等 5~10 秒 | 最有"人味"；也可能编造做不到的步骤，且选框会从"即时"变成"等结果" |

推荐 B 的理由：那 15 张卡的做法本来就是我们预置的（步骤、交付物我们早知道），
用模型重写等于把已知答案交给模型猜；只有"其它"这条路没有预置答案，才值得花一次调用。
这也和参考产品的做法一致——LobeHub 那些卡片本身就是模板，不是现场生成的。

若走模型，必须按我们既有的规矩来（和四个上游模块同一条）：输入只给"选项 + 用户那句话 +
允许的动作清单 + SKILL.md 格式规范"；输出做结构校验（小节齐全、≤12000 字、不出现未接通能力）；
校验不过或超时 → **退回模板版**，并在卡上如实标一句"这张卡的说明是通用骨架"，不假装写好了。

### 5.2 一张卡要写三样，不是只写说明书

`skill` 这个对象除了 `instructions`，还支持 `parameters`（输入：名称 / 是否必填 / 提示 / 默认值）
和 `workflow`（步骤）。第一张卡三样都要写，因为它们是三处界面的数据源：

| 字段 | 谁在用 |
| --- | --- |
| `instructions`（markdown 四小节） | 卡片详情里的"它能替你做 / 步骤 / 交付什么 / 完整说明" |
| `parameters` | 点「用它做一件事」时弹出的输入框（问你这次要喂什么） |
| `workflow` | 步骤数（决定这次任务的预算：步骤数 + 2 个单位） |

三样来自同一份设计，就不会出现"卡片上写了输入、真去用时却不问你要"这种前后不一致。

### 5.3 说明书不是终稿

`tool.save` 每次都会生成一条 `skill_version`（版本化），所以以后能改版而不动历史任务；任务被验收后，
`captureTaskExperience` 会把"已验收的做法"沉淀成一条**方法经验记忆**（绑定工具版本，同类任务可复用）；
同类做法被反复用到，Foundry 那条路才会起草**新版本**的 skill（它要求同类做过 ≥2 次）。
也就是说：初始化给的是**起点版本**，说明书的厚度是靠"用过并验收"长出来的，不是靠开局一次生成。

## 6. 边界与例外

| 情况 | v1 怎么处理 |
| --- | --- |
| 用户全程跳过 | 给默认卡（探索「查资料并核实来源」），文案说明"先给你这张最通用的，随时能改" |
| 用户选了"其它"自由文本 | 只生成 1 张，标题取文本前 20 字；说明书用通用骨架 + 原文 |
| 已经有卡但 0 成果 | 不再进整套初始化；空态换成一句话 +「再添一张」，按同一套三步走 |
| 中途退出 | 记一半：下次进来从没完成的那一步继续（不重头问） |
| 想删掉刚生成的卡 | 卡片详情本来就能归档，不用为初始化单独做删除 |
| 以后要"渐进式引导"更多卡 | 第一张卡被验收后，卡片详情里出现「再添一张（同类／换一类）」——本期只留钩子，不做 |

## 7. 与现有东西的关系（避免重复建设）

| 已有的东西 | 关系 |
| --- | --- |
| 能力洞察的轻量测试（问卷） | **互不替代**：问卷管"五维起点"，初始化管"第一张卡"。会议说问卷方案暂时搁置，本期不动它 |
| Skill Foundry 自动起草 | 两条来源并存：Foundry 走"同类做过 ≥2 次"，初始化走"用户自己声明"。产物都是 `skill`，用 `source` 区分，互不覆盖 |
| 手动"创建工具"（首页那一屏） | 上游同一套三步组件；那屏不归我们，改动要跟同事约。我们这边先在第二页空态上落地 |
| 记忆 / 理解度 | 第 2 屏的偏好直接进记忆（低风险自动学、带来源），是理解度的第一批真实信号 |
| 卡片等级与分数 | 初始化卡一律 Lv.1 发现 / 0 成果 / 无分数，不参与任何"白送分" |

## 8. 观测与验收（怎么算这版做成了）

埋点三条：进入初始化 / 每一步完成 / 生成成功（含生成张数与所选选项）。

验收（真机跑一遍）：

1. 新账号进第二页空态 → 30 秒内拿到 **≥1 张可用能力卡 + 1 条任务草稿**；
2. 卡片详情能正确渲染"它能替你做 / 步骤 / 交付什么"，不是压平的 markdown；
3. 点「用它做一件事」能真的建出任务并跑；
4. 卡的等级仍是 Lv.1、0 成果、无分数；跑完并验收之后，分数与等级按既有口径开始动；
5. 跳过、"其它"、已有卡这三种路径都不出现死按钮或空屏。

## 9. 需要拍板的五件事（文档里已给推荐，可改）

1. **第 1 屏选项表**：现在是我按五系统各 3 个起的草案（15 张），要不要删改或换成你们已有的版本？
2. **一次生成几张**：**已定为 1 张**（2026-09-29 改；原来是"最多 3 张"）。"我不知道选什么"直接给最通用的那一张。
3. **第 2 屏的四组偏好**：就用"结论/过程 · 简短/详细 · 引用来源 · 独立复核"这四项，还是换成别的？
4. **旧出口**：「去和 Elfred 说」保留为次级入口（我建议保留），还是彻底去掉？
5. **说明书写法**：A 纯模板 / **B 模板 + 其它走模型（我推荐）** / C 全走模型 —— 见 5.1。
6. **落地顺序**：先在第二页空态上（我们自己的页），首页「创建工具」那一屏要不要同步换（需要跟同事约）？

## 10. v1 实际落地（2026-09-29，初步实验完成）

已按本设计实现，范围只限"能力卡初始化"这一块（其他页面没动）：

| 设计里的东西 | 落地情况 |
| --- | --- |
| 第 1 屏：五系统 × 3 的预置卡 + 「其它」+「我不知道选什么」 | 已实现（15 张预置卡在 `app/v28/core/card-onboarding.mjs`，前后端共用同一份） |
| 第 2 屏：四组偏好（有默认值） | 已实现；「其它」那张卡在这一屏还能改归属系统 |
| 第 3 屏：预览 + "Lv.1 发现、0 成果"说明 | 已实现 |
| 生成：skill（active、source=onboarding）+ 任务草稿 + 初始化记录 | 已实现；说明书四小节、`parameters`（输入）、`workflow`（前置步骤）一起写 |
| 偏好进说明书「注意」/ 任务 constraints / 记忆 | 已实现；**只把"改成非默认值"的那几条记成理解**，不给记忆添噪音 |
| 重复选同一张卡不生成第二张 | 已实现（按 `onboarding.preset_id` 去重，回执里如实报"已经有了"） |
| 入口：第二页空态主按钮 +「去和 Elfred 说」降级为次级 | 已实现 |
| 已有卡时"再来一张" | 已实现：放进已有的「我的工具/导入」面板里当一行，不新增按钮 |
| 「其它」走一次模型把它翻成说明书 | **本版没做**：现在用模板把原文嵌进说明书（"什么时候用"就是用户那句话）。模型增强不改数据结构，随时能加；加之前先按 5.1 定好校验与降级规则 |
| 首页「创建工具」那屏同步换 | 没动（不归我们，要跟同事约） |

**自测是这一块的全量自测**（新增专项探针 `tools/page2-checks/onboarding-audit.mjs`，40+ 条断言）：
空态入口 → 三步走完 → 生成 → 逐条核对（active skill / 四小节说明书 / 输入 / 前置步骤 / 任务草稿 / 初始化记录 /
只有改过的偏好进理解）→ 卡组与卡详情渲染（不是压平的 markdown）→ **真的用它做一件事**：
带输入建任务 → 确认 → 启动 → 跑出回执（work / review / repair 全 succeeded，停在等人验收）；
再加三条边界路径：跳过（给默认两张）、"其它"（原文进说明书、系统按用户选的归）、已有卡再来一张（总数 3 张）。
原有两条探针（`live-audit` 9 项、`flows-audit` 六条流程）复测未回退。

**自测当场抓到并修掉的两个真问题**（都是"不该等用户发现"的那类）：

1. **面板被底部导航盖住**：第一版自己写 `position: fixed` + z-index，结果"下一步 / 生成"按钮在，但点不到。
   改成复用项目里那套共用底部弹层（`RootPortal` + `v278-sheet-backdrop` + `v279-setting-sheet`），
   并给面板留出底栏高度。现在探针里有一条机械断言：**滚到底之后，面板里任何按钮都不能压在导航下面**。
2. **探针自己的固定等待不稳**：应用启动慢或新账号落在"首次对齐"页时，`sleep(3s)` 之后找不到底部导航。
   三个探针改成共用一个入口函数（`tools/page2-checks/_page.mjs`：等元素出现，必要时跳过对齐页），
   这类偶发不再当成产品问题。

**与设计稿的差异，一句话**：除了"「其它」暂不调模型"和"首页那屏没动"，其余按设计实现；
预置卡的做法（步骤、输入、交付物）是本版新写的文案，属于可改内容，不影响结构。

### 10.1 后续调整（2026-09-29，v1.1）

| 调整 | 落地情况 |
| --- | --- |
| **一次只做一张卡**（原来是"最多 3 张"） | `MAX_CARDS_PER_RUN` 改为 1；第 1 屏改成单选（再点一下取消，换个选项就替换）；「其它」和现成卡二选一；"我不知道选什么"改为直接给最通用的那张（查资料并核实来源）；第 3 屏与结果页文案跟着改成单数；重复选同一张仍只报"已经有了" |
| **禁用状态的主按钮要看得清字** | 原来靠 `opacity`，而 `.v277-device button:disabled{opacity:.44}` 的优先级更高，黑底按钮被压成"近白的底 + 浅灰的字"。改用 `.onboardSheet` 前缀抬高优先级 + 明确配色（浅底 `#eef1f2` / 深灰字 `#6f7981`） |
| **「用它做一件事」不再把说明书倒进输入框** | 说明书改成对话页输入框上方的一张附件卡（卡名 + ✕），用户照常写自己的话；发送时把说明书拼进消息正文，发出去的内容和以前一致。详见 `app/v28/features/pages24/README.md` |

自测：`tools/page2-checks/onboarding-audit.mjs` 按新口径重写（单选替换、跳过给一张、结果只落一张卡与一条草稿、
禁用按钮 + 附件卡的可读性），三条真机探针与 326 项目标级测试全过。

### 10.2 再改：从"填表三步"换成分支选择树（2026-09-29，v2）

真机走了一遍三步流程后的反馈："选起来很吃力"。核过之后确认问题不在选项多少，而在**三段之间没有因果**：
第一屏选哪张卡都不影响第二屏的四组偏好，读起来像填表；而那四组偏好本来就是我们该在
使用中学的东西（理解度 / 记忆那套）。参考产品（LobeHub 开源实现、Hyperknow）都不这么引导 ——
详见 `docs/调研-第一张能力卡该怎么问.md`。

现在的流程：**每页 3 个选项，选完决定下一页；路径决定内容，不只决定卡**。

| 层 | 谁决定 | 例子 |
| --- | --- | --- |
| 骨架 | 某个选项把卡定下来 | 「查资料并核实来源」固定三步 |
| 内容片段 | 路径上每个选项各带一两条 | 资料从哪来（只用我给的 / 允许联网 / 都行）、给谁看（老师 / 队友 / 自己） |
| 偏好 | 预览页的「再细一点」，默认不动 = 默认值 | 先给结论 / 先给过程、简短 / 详细、引用来源、独立复核 |

于是**同一张卡走不同路径 = 两份不同的 skill**（交付、注意、输入都可能不同）。题面规则：
① 每页最多 3 个选项、说人话（不出现系统名）；② 每题都能走"都不太对，我自己说一句"
（按关键词落到某张现成卡，落不到才造一张"其它"卡）；③ 轮数按分支走，2~4 页。

落地：`core/card-onboarding.mjs` 里新增 `CARD_FRAGMENTS`（内容片段表，带互斥组）与
`CARD_QUESTIONS`（题目树）+ `resolvePath`；`composeSkillMarkdown / composeTaskDraft /
composeToolParameters` 改成吃"骨架 + 片段"；服务端 `card.onboard` 新增 `path` 入口
（老的 `preset_ids` 仍然认，"再来一张"与脚本在用）；界面从三步向导换成树 + 预览 + 「再细一点」。
树覆盖 14 张预置卡，"核对交付物是否达标"留给"我自己说一句"这条路。

顺手修掉一个被新内容触发的真 bug：能力卡说明书里会写"不联网补充""允许联网"，
原来的联网意图识别把它当成"本轮要联网"，再把整段消息（600+ 字）当关键词，接口直接 400
（`INVALID_WEB_QUERY`）。现在"不联网 / 不搜索"也算关掉联网，且自动模式下超长消息降级成普通对话。
